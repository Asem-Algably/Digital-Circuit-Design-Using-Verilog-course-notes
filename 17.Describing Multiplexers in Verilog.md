**in this module we are going to create a mux_2x1_nbit using behavioral representation**
### conditional operator
- we can do that using the if statement but we can also use one of Verilog operators to achieve a similar effect which is the conditional operator
- the conditional operator syntax is similar to the ternary operator in programming languages
```verilog
status = condition ? expression_if_true : expression_if_false;
```
- the condition operator accepts 3 parameters a condition and 2 values, if the condition is true the operator will return the first value otherwise it will return the second one 
so we can code our multiplexer like that
```verilog
module mux_2x1_nbit(
    input w0,
    input w1,
    input s,
    output f
    );
    // here we are using the assign key word 
    // since this is a continuous assignment
    assign f = s ? w1 : w0;
endmodule

```
but actually this code isn’t a behavioral modeling, this is data flow, actually you could use Verilog operators in any modeling type but in order for it to be a behavioral modeling we would have to include it inside and always block
as we discussed in a previous module to construct an always statement we start by defining your sensitivity list which are the parameters that once changed your output would get updated so we can change the code like that
```verilog
module mux_2x1_nbit(
    input w0,
    input w1,
    input s,
    output reg f
    );
    
    always @(w0,w1,s)
    begin
        // procedural assignment 
        f = s ? w1 : w0;
    end
    
endmodule
```
- notice how we changed the f to type `reg` and removed the `assign` word since now this is a procedural assignment 
- the reason we are using `reg` is a bit more historic and we aren’t really dealing or need a memory element here but this is the way Verilog works
### parametrizing our module
now we are ready to make our code more usable by parametrizing it like this code
```verilog
module mux_2x1_nbit
    #(parameter n=3)(
    input [n-1: 0] w0,
    input [n-1: 0] w1,
    input s,
    output reg [n-1: 0] f
    );
    
    always @(w0,w1,s)
    begin
        f = s ? w1 : w0;
    end
    
endmodule
```

### 4x1 multiplexer
now let’s scale things up more and create a 4x1_mux
like the last module we will use the operational operator in a behavioral modeling 
- since we have double the conditions we would need to cascade the conditional operators like that
```verilog
module mux_4x1_nbit
    #(parameter n = 4)(
    input [n-1 : 0] w0,w1,w2,w3,
    input [1:0]s,
    output [n-1 : 0] f
    );
    // mux logic using conditional operator
    assign f = s[1]? (s[0]? w3: w2):(s[0]? w1: w0);
endmodule
```

---

as you might see this code isn’t the most readable so we can use other behavioral modeling techniques like an if statement so our code might look like that
```verilog
module mux_4x1_nbit
    #(parameter n = 4)(
    input [n-1 : 0] w0,w1,w2,w3,
    input [1:0]s,
    output reg [n-1: 0] f
    );
    
    //  using if statements which is also called Priority Routing Networks
    always @(w0, w1, w2, w3, s)
    begin
        if (s == 2'b00)
            f = w0;
        else if (s == 2'b01) // this can be s == 1 (decimal)
            f = w1;
        else if (s == 2'b10)
            f = w2;
        else if (s == 2'b11)
            f = w3; 
        else
            f = 'bx;               
    end
endmodule
```
- as a general rule of thump you have to define a default statement (the last else) that would run if none of the conditions are satisfied so that we can test if something went wrong
another different way to do it is using a case statement 
```verilog 
module mux_4x1_nbit
    #(parameter n = 4)(
    input [n-1 : 0] w0,w1,w2,w3,
    input [1:0]s,
    output reg [n-1: 0] f
    );
    
    // using the switch case
    always @(w0,w1,w2,w3,s)
    begin
        case(s)
            2'b00: f = w0;
            2'b01: f = w1;
            2'b10: f = w2;
            2'b11: f = w3;
            default: f = 'bx;
        endcase
    end
endmodule
```
- by the way if you have more than a statement inside the case you should use a `begin` and `end` but since we only have one statement here (the procedural assignment) it’s redundant
- like the f statement don’t forget to add a default value when things go wrong

### generalized one bit multiplexer
now let’s try using the for loop but instead of parametrizing the module in terms of the bit count we will parametrize it in terms of channels number 
as you can notice the number of selector bus bits should be the ceiling of the log of the MUX channels, we can achieve this value using the system function `$clog2(n)`
```verilog
module mux_generic_1bit
    #(parameter N = 4)(
        input [N - 1: 0] w,
        input [$clog2(N) - 1:0] s,
        output reg f
    );
    
    integer k;

    always @(w, s)
    begin
        f = 'bx;
        for (k = 0; k < N ; k = k + 1)
            if (k == s)
                f = w[k];
    end
endmodule
```
- as you can see the k is defined by the keyword `integer` not `genvar` since this isn’t a generate block but rather an `always` statement
- note that we are setting the value of f as `'bx` as default value at the beginning to prevent f from adding an RTL latch

> [!NOTE]
> as you can see we generalized our multiplexer here in terms of bus bits, but what if we want to generalize it both in terms of bus bits and input channels, you might think of using a multi dimension array like what we would normally use in `C` for such a problem but there is a problem which is that multi dimension arrays aren’t supported in plain Verilog and would require system verilog to use such a feature
