**in previous chapters we discovered how to code an adder and we learned more about arithmetic operators and signed numbers and in this chapter we will create an adder circuit using arithmetic operators instead of defining logic ourselves**

so basically you can use Verilog arithmetic operators instead of manually defining circuits like that
```verilog
assign s = x + y;
```

### but what if we want to output the carry out
we can increase the size of our calculation by one binary place and see if it got populated or not
note that once concatenating 0 with the rest of your numbers you have to define that it’s a 1 bit zero since by default Verilog would assume that it’s a 32 bit number
```verilog
assign sum = {0,x} + {0,y}; // <= this is wrong this it would be 
                            // consider a 32 bit number

assign sum = {1'b0, x} + {1'b0, y}; // <= this is the right method
```
we can use this pattern to calculate the carry out so we can compute the output as the sum without the last bit and the carry out as the last bit like that
```verilog
module arithmetic_operators
    #(parameter n = 4)
    (
        input [n - 1:0] x,
        input [n - 1:0] y,
        output [n - 1:0] s,
        output cout, overflow
    );
    
    wire [n:0] sum;
    assign sum = {1'b0, x} + {1'b0, y};
	assign s = sum[n - 1:0];
    assign cout = sum[n];
endmodule
```

but actually we don’t have to increase the size of our inputs since Verilog automatically increases the size of all inputs and outputs to the largest input or output in the calculation, so since the size of the sum vector is `n` it would increase the size of the inputs form `n-1` to `n`  so we can turn the code to this

```verilog
module arithmetic_operators
    #(parameter n = 4)
    (
        input [n - 1:0] x,
        input [n - 1:0] y,
        output [n - 1:0] s,
        output cout, overflow
    );
    
	wire [n:0] sum;
    assign sum = x + y;
    assign s = sum[n - 1:0];
    assign cout = sum[n];
endmodule
```

but another problem we encounter is that while working with signed numbers when  we concatenate a zero to the left it can miss the sign of the number so a solution to that problem is to use a signed type in the input definition

```verilog
input signed [n - 1:0] x,
```

this way when we expand x by 1 if the sign was would it would get replicated to the expanded bit even if we replicated it with two it would be replicated the the left most bit, note that by default Verilog replicates the sign on expansion so you don't really need to specify the signed type but if you face bugs during such procedure you can use it

another shorter way of assigning the s and the cout is to concatenate the s and the cout and assign them to the sum, it’s kind of similar to array deconstruction in languages like JavaScript

```verilog
assign {cout, s} = x + y;
```

and finally for the overflow we could use the same method we used in the adder_subtractor circuit by checking if the sign of the inputs is the same as the sign of the outputs

```verilog
assign overflow = (x[n - 1] & y[n - 1] & ~s[n - 1]) |
				  (~x[n - 1] & ~y[n - 1] & s[n - 1]) ;
```
