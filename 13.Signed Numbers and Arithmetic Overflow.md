we can represent negative numbers in 3 ways:-
- sign and magnitude
- first complement
- second complement

>[!caution] cautions while working with singed numbers
>- you have to be careful when adding two signed numbers because this can lead to overflow errors
>- the carry out is meaningless in signed numbers arithmetic

### how to check if an overflow exists
- the first way is to see if the carry in and carry out of the last bit is different or not, if they are different this means that there is an overflow, otherwise there is not
- the second way is to check if the sign of the inputs after summing is different that the sign of the output, in other words if the sign of both inputs is positive and the summation of them is negative then an overflow has happened and if the inputs are negative and their sum is positive then an overflow has happened, if one number is positive and the other is negative an overflow couldn’t happen at the first place so we don’t check it

### designing a generalized adder subtractor with overflow flag
```verilog
module adder_subtractor
    #(parameter n = 4) (
    input [n - 1:0] x, y,
    input add_n,
    output [n - 1:0] s,
    output c_out,
    output overflow
    );
    
    // declare different signals
    wire [n - 1: 0] xored_y;
    
    // generate several XOR gates
    generate
        genvar k;
        
        for (k = 0; k < n; k = k + 1)
        begin: bit
            assign xored_y[k] = y[k] ^ add_n;
        end
    endgenerate
    
    // Instantiate an n-bit adder
    rca_nbit #(.n(n)) adder0 (
        .x(x),
        .y(xored_y),
        .c_in(add_n),
        .s(s),
        .c_out(c_out)
    );
    
    // generate an overflow flog by looking the the signes
    // of x, xored_y, s
    // we look at the xored_y because we only care about the adder portion of the circuit
    assign overflow = (x[n - 1] & xored_y[n - 1] & ~s[n - 1]) |
                      (~x[n - 1] & ~xored_y[n - 1] & s[n - 1]);
    
endmodule
```

>[!note] why we are checking the overflow on the **xored_y** not **y**
>when we discussed the two ways we can check for the overflow notice that we discussed only the overflow of the summing operation, since for subtraction what we only do is that  we take the 2’complement of the second argument making it negative and then then adding it to the first, so when we check the overflow we only care about the summation of the signed number since the subtraction is achieved implicitly not explicitly 

to finish things up when we are dealing with **unsigned** number the **overflow** flag doesn’t matter and when we are dealing with the **signed** numbers the **carry out** flag doesn’t matter
