while working with conditional statements in c every thing is performed sequential but in verilog every thing is happening concurrently at the same time through something called a routing network, popular options for routing networks include:-
- priority routing networks (if-else, non-parallel case)
- multiplexing network (parallel case)

a sequence of if else statements would probably get routed using the priority routing network which create a circuit consisting of a series of multiplexers back to back

but note that priority routing networks might create a propagation delays if you were working with high speed circuits or high frequency ones

a case statement would probably get routed using the multiplexing network which creates the circuit using a large input multiplexer instead of multiple ones back to back

> [!TIP]
> **when we use priority routing networks or multiplexing networks**
>generally speaking we use the priority routing network if we are writing code with priority like a priority encoder while we use the multiplexing network with performing big truth tables like seven segment displays decoders 

writing behavioral code in verilog is important and you should understand, think and anticipate the circuit that would be generated by your code 

> [!WARNING]
>when we are working with outputs inside conditional statements we might get a storage element with it or a latch which isn’t at all what we want, in combinational circuits the output should be a function of only and only the current inputs
>
>the reason for that is in an always statement is the way always statements work which is that variables try to keep it’s previous values if not assigned a new one

### how to avoid latches in combinational circuits
- make sure that all branches of the if and case statements are included (use else and case’s default)
- make sure that all outputs are assigned in all branches (use default values before your conditional block)
