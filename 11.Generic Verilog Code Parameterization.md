### how to specify a parameter to a Verilog module
- you can do that by adding `#` and using the keyword parameter and you can even define them parameters next to each other
- the value of the parameter is specified once the module is used but  in case if it’s value hasn’t been provided by the designer you can provide it a default value using the `=` similar to function arguments in most programming languages
- notice how the parameters are defined outside the inputs and outputs parentheses and the reason is that simply it’s not an input or an output but rather a parameter which is totally a distinct concept

```verilog
module demo_module  
    #(parameter a = 4, b = 5) ( 
    input [a - 1:0] x, y,
    output [b - 1:0] s
    );
```

### creating repeated logic structures
- `generate` code block is used for replicated hardware structures or in other words to generate repeated  instances of the same module
- `for` block or the for loop in Verilog is similar to it’s structure in C programming language
- to specify a variable in the `generate` block you can use the key word `integer` but since for loops are a very specific case you can use the `genvar` type which is an integer that cannot take on negative values
- you provide naming for  your instances in the for loop by providing the name after the begin keyword
```verilog
// generate replicated hardware structures
    generate
        // genvar type is similar to integer, but it can only
        // take positive values
        genvar k;
        
        // Loop iterator must be of type genvar
        // k++ and k-- cannot be used
        for (k = 0; k < n; k = k + 1)
        begin: stage // <= instance name
			// instance definition goes here
        end
    
    endgenerate
```

### how to instantiate a parametrized code
simply before defining the inputs and outputs use a `#` and start defining your parameters in a parentheses but 
- not that like your ports you can use order parameter connection or name parameter connection and of course the later is the best
```verilog
demo_module #(.n(16)) demo0 (
	// port definitions
);
```

>[!TIP] but wait is `generate` behavioral code?
>note that the use of the generate block doesn’t make your code behavioral because it’s used for generated logic structures so It could be used with structural code or behavioral code 

### making a parameterized ripple carry adder
first we need to parameterize the module like that
```verilog
	module rca_nbit 
    #(parameter n = 4) (
    input [n - 1:0] x, y,
    input c_in,
    output [n - 1:0] s,
    output c_out
    );
    
    wire [n:0] c;
    assign c[0] = c_in;
    assign c_out = c[n];
    
    // generate replicated hardware structures
    generate
        // genvar type is similar to integer, but it can only
        // take positive values
        genvar k;
        
        // Loop iterator must be of type genvar
        // k++ and k-- cannot be used
        for (k = 0; k < n; k = k + 1)
        begin: stage
            full_adder FA (
                .x(x[k]),
                .y(y[k]),
                .c_in(c[k]),
                .s(s[k]),
                .c_out(c[k + 1])
            );
        
        end
    
    endgenerate
endmodule
```

now let’s use it in an instance
we will create a module that uses the rca_nbit to create two ripple carry adders of different sizes, the first is 16 bit and the second is 34 and yes it’s 34 
I know what’s on your mind but let’s just keep moving 😅
```verilog
module multi_adders(
    input [15:0] a, b,
    output [15:0] s_ab,
    output c_out_ab,
    input [33:0] x, y,
    output [33:0] s_xy,
    output c_out_xy
    );
    
    rca_nbit #(.n(16)) adder_16 (
        .x(a),
        .y(b),
        .c_in(0),
        .s(s_ab),
        .c_out(c_out_ab)
    ); 
    
    
    rca_nbit #(.n(34)) adder_34 (
        .x(x),
        .y(y),
        .c_in(0),
        .s(s_xy),
        .c_out(c_out_xy)
    ); 
endmodule
```
